# 34 — Zero-to-Hero Roadmap

This is the study order for the whole handbook: 123 topics on five levels, from your first shell session to running game days as a lead. Each level matches a career stage from the [career ladder](40-career-ladder.md) and ends with a timed exit test. The same data drives the 3D course map, so this page is the text version for offline and terminal reading.

| Level | Career stage | Topics | You are trusted to | Exit test |
|---|---|---|---|---|
| L0 Foundations | Fresher | 14 | do a defined task correctly on one server | 30 min: sudo user with key-only SSH, five largest files under /var, every field of ls -l, a bad commit reverted |
| L1 Operator | Junior | 22 | keep services running from runbooks | 5 min per port: process, unit, config file and log command |
| L2 Troubleshooter | Mid-level | 33 | own a system and find the broken layer | 15 min: 'the site is down', broken layer named with evidence |
| L3 Platform | Senior | 40 | build the platform others deploy to | one weekend: an Apache app in a container behind Dokploy, built by GitLab CI, pushed to Harbor, rollback tested |
| L4 SRE | Senior / Lead | 14 | make reliability a property of the team | game day: alert, fix, published one-page postmortem |

> Commands are examples to study and run on a test VM, never on servers people depend on. UPPERCASE words are placeholders, addresses come from the documentation ranges and names use example.com. KodeKloud titles were checked on 3 October 2026 and can change.

## How to use this roadmap

1. **Place yourself.** Spend ten minutes on [Place yourself in ten minutes](40-career-ladder.md#place-yourself-in-ten-minutes). Stage and level are the same scale: Fresher L0, Junior L1, Mid-level L2, Senior L3, Senior / Lead L4.
2. **Prove the levels below you.** Run their exit tests under the timer. Pass, and you skip the topics; fail, and the topics you stumbled on are your study list.
3. **Work your level in path order.** The topic lists below follow the guided path. A topic's prerequisites are always earlier on the path.
4. **Break it, then fix it.** Every topic has a practice drill, a 'symptom → first command' list and an exit check. A topic is done when you pass its exit check, not when you finish the video.
5. **Use the playbooks whenever something breaks,** whatever your level. The level only says when you are expected to run a playbook alone.

## Study method

Every topic uses the same five steps, so you never have to decide what to do next.

| Step | Time | What you do | Why |
|---|---|---|---|
| 1. Learn | 30–60 min | The KodeKloud lesson and its lab for a new topic; the handbook note for a refresher | KodeKloud labs grade you in a real terminal, so you learn by typing |
| 2. Handbook note | 10–20 min | Read the linked handbook section with its sample output | It shows the real problem and the exact commands on your stack |
| 3. Lab | 20–30 min | Do the topic's drill on a KodeKloud playground or your homelab, and break something on purpose | Courses teach building; your job is fixing |
| 4. Playbook drill | 15–30 min | Fix the break with the matching playbook, under a timer | It proves the skill transferred out of the course |
| 5. Exit check | 5 min | Pass the topic's exit check, write the five-line note, mark the topic done | Evidence, not hours, moves you up a level |

New topics start with KodeKloud. Refreshers (most of L0 and L1 for you) start with the handbook note. Where KodeKloud has no course (tcpdump and strace, Traefik on Docker, Dokploy, Wazuh, Linux performance, WireGuard and mesh VPNs, wiring the open-source tools together), the topic starts with the handbook and the official documentation, and the map says so. The full method is in [Learning with KodeKloud](40-career-ladder.md#9-learning-with-kodekloud).

## Weekly rhythm

Tie each habit to something that already happens, so the practice does not depend on finding free time.

| When | What | Time |
|---|---|---|
| Workday morning | One [SadServers](https://sadservers.com/scenarios) scenario or one [100 Days of DevOps](https://kodekloud.com/100-days-of-devops) task, alternating. When the timer runs out, read the solution and write one line on what you missed | 30 min |
| Two evenings | Steps 1–3 for your current topic | 60 min each |
| Weekend homelab block | Steps 4–5 for the week's topic, then a CKA break-and-fix session | 2–3 h |
| Any incident at work | The five-line note: symptom, first wrong guess, deciding evidence, fix, what to check first next time | 5 min |
| Sunday evening | One real postmortem from [Kubernetes Failure Stories](https://k8s.af/) or [Dan Luu's list](https://github.com/danluu/post-mortems); name the failing layer before you reach the root cause | 20 min |

Until you pass the CKA, the CKA course takes the evenings and everything else runs on the morning rep. The career-ladder version of this rhythm is in [Your weekly rhythm](40-career-ladder.md#your-weekly-rhythm).

## Your first 30 days

Your starting point: Apache was moved to ports 81 and 444 so that Dokploy's Traefik could take 80 and 443, the legacy hostnames still need proper routes, and you are on the CKA track. The plan finishes the live migration first, because it is real work with real risk, and keeps the CKA in the evenings. It jumps ahead to two L3 topics (Traefik and the legacy routes) on purpose; everything else follows the levels.

### Week 1: close the port story

- **Day 1:** place yourself, then run the L1 exit test on your own Dokploy host for ports 81, 444, 443 and 3000 ([Who owns this port? Port → PID → unit → logs](#map.port-ownership)). Write the five-line note for the original 443 clash ([Incident notes and runbooks](#map.incident-note)).
- **Evenings:** CKA Core Concepts and kubectl speed ([Kubernetes architecture and kubectl](#map.k8s-architecture)).
- **Mornings:** SadServers easy scenarios.
- **Weekend:** replay the case on the KodeKloud Ubuntu playground: Apache with two vhosts on 81/444 behind a Traefik container ([Traefik v3: entryPoints, routers, services](#map.traefik), [Phase 7 of the case](21-case-apache-443-dokploy.md#8-phase-7-route-the-legacy-apache-sites-through-traefik)).
- **Done when:** you can name the owner of every port on the host, and the lab replay answers through Traefik with curl --resolve.

### Week 2: finish the migration for real

- **Evenings:** CKA pods, Deployments, probes and config ([Pods, Deployments, ConfigMaps and Secrets](#map.k8s-workloads)).
- **Mornings:** badssl.com TLS errors and the break-DNS-three-ways drill ([TLS, certificates and chains](#map.tls-certs), [DNS in depth: resolver path, caches, TTL](#map.dns-deep)).
- **Weekend:** write the change request first ([Example CR: retire system Apache](33-learn-cicd-iac-sre.md#example-cr-retire-system-apache)). Then, in a window, add a Traefik route per Apache site, fix certificate renewal, close 81 and 444 from outside and restore client IPs ([Finish it: Traefik routes legacy vhosts](#map.traefik-legacy-routes)). Finish with the [post-deployment checklist](35-deployment-patterns.md#6-post-deployment-checklist) and an outside scan ([Docker bypasses UFW](#map.docker-firewall)).
- **Done when:** every legacy hostname answers through Traefik on 443 with a certificate that renews, and a scan from outside shows only SSH, 80 and 443.

### Week 3: Kubernetes networking and the site-down walk

- **Evenings:** CKA Services, CoreDNS, Ingress and NetworkPolicies ([Services, endpoints and cluster DNS](#map.k8s-services-dns), [Ingress, Gateway API and NetworkPolicies](#map.k8s-networking)).
- **Mornings:** site-down drills and SadServers scenarios tagged dns, nginx or ssl ([Site down: walk the request path](#map.site-down-walk)).
- **Weekend:** build the kubeadm homelab ([kubeadm homelab: build, upgrade, back up](#map.kubeadm-cluster)) and run [break-and-fix drills](31-learn-kubernetes.md#22-twenty-timed-break-and-fix-drills) 1–10.
- **Done when:** your cluster runs and you fix a broken Service, DNS lookup and Ingress in about 6 minutes each.

### Week 4: troubleshoot under a timer

- **Evenings:** the CKA Troubleshooting section and the free Kubernetes Challenges ([Kubernetes troubleshooting: bottom-up](#map.k8s-troubleshooting)).
- **Mornings:** container failures and the 60-second checklist with stress-ng ([Docker incidents: restart loops, 137, DNS, disk](#map.container-incidents), [Why is it slow? The 60-second checklist](#map.slow-system)).
- **Weekend:** have a colleague run the L2 exit test on a lab site, do drills 11–20, and publish a sanitized write-up of the migration ([Building proof](40-career-ladder.md#10-building-proof)).
- **Done when:** you pass the 15-minute site-down test and the write-up is in your public notes repo.

### Day 30 checkpoint

Mark these done on the map: Who owns this port? Port → PID → unit → logs; Incident notes and runbooks; Free a port by shifting Apache to 81/444; Traefik v3: entryPoints, routers, services; Finish it: Traefik routes legacy vhosts; Kubernetes architecture and kubectl; Pods, Deployments, ConfigMaps and Secrets; Services, endpoints and cluster DNS; Site down: walk the request path. The next 60 days: scheduling and storage, cluster maintenance, mock exams and killer.sh, then the exam ([Milestone: pass the CKA](#map.cka-exam)). After the CKA, build the pipeline ([GitLab CI → Harbor: build, tag, push, deploy](#map.gitlab-ci-harbor)) and do the L3 capstone ([Milestone: Apache app to Dokploy (L3 exit test)](#map.milestone-senior)). The 14-day and 90-day versions are in [Your personal next steps](40-career-ladder.md#13-your-personal-next-steps).

## Where to go after L4

- **Teach it.** Run game days for others, review their postmortems and mentor juniors ([Mentoring juniors](39-learn-senior-architecture.md#mentoring-juniors-l3-senior)).
- **Widen on purpose.** CKS or CKAD only when your job needs them; the order is in [Certifications in order](40-career-ladder.md#certifications-in-order).
- **Keep the proof growing.** One sanitized runbook or postmortem per level you clear ([Proof by stage](40-career-ladder.md#proof-by-stage)).
- **Look past L4.** Staff, principal and SRE paths are in [Beyond L4](40-career-ladder.md#beyond-l4); for performance depth, Brendan Gregg's [Linux Performance](https://www.brendangregg.com/linuxperf.html) page.
- **Keep the morning rep.** Thirty minutes of a broken server a day is what keeps the skill.
